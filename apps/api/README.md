# apps/api — будущий бэкенд (зарезервировано)

Сейчас здесь нет кода. Всё в MVP работает без сервера: контент лежит в JSON, прогресс хранится в `localStorage`.

## Что сюда придёт

| Функция | Что нужно | Связь с текущим кодом |
|---|---|---|
| **Оплата и подписки** | ЮKassa, вебхуки, тиры `free`/`premium`/`supreme` | `engine/tiers.ts`: `DEFAULT_USER_TIER` заменится на уровень с сервера |
| **Профили и вход** | Вход через Telegram (проверка `initData`) и/или email | Экран `/soon/profile` |
| **Прогресс на сервере** | Своё хранилище для `ProgressStore` | `engine/storage.ts`: экраны менять не придётся |
| **Ачивки, стрики, шкала «насколько ты себя знаешь»** | Подсчёт по истории прохождений | `ProgressData` |
| **Комнаты по ссылке** | Создание комнаты (Supreme), гости бесплатно, real-time | Механики `engine` подходят для мультиплеера: они чистые |
| **ИИ-агенты (Ultimate)** | Ключи моделей **только здесь**, лимиты, кризисный протокол, 152-ФЗ | `packages/agents`: типы и правила |
| **«Предложи своё»** | Приём карточек, модерация, `source: "community"` | `content/schema.ts`: поле `source` у карточки |
| **Аналитика спроса** | Сейчас — Vercel Analytics (`deeper_click`) | `apps/web/lib/analytics.ts` |

## Правила

- Секреты (ключи ЮKassa, моделей, токены) — только в переменных окружения сервера, никогда в коде.
- Данные пользователей хранить в РФ (152-ФЗ). Персональные данные — по минимуму.
- Функции знакомств и чатов между пользователями требуют отдельной модерации и разделения по возрасту (см. `docs/ARCHITECTURE.md`).
